# ramble: a TUI markdown reader backed by markdown LSPs

Status: approved design, revised after review panel (see "Review log")
Date: 2026-10-07

## Problem

Today, reading markdown in the terminal takes two tools:

- `m` (`~/dotfiles/local-bin/.local/bin/m`) wraps glow and pages the
  output through `less -R -X`. It works around four glow problems: the
  slow pager, losing truecolor when stdout is a pipe, a hang caused by the
  `TERM` setting, and paragraphs that do not reflow (the wrapper runs
  prettier first). It cannot follow links. It deliberately leaves the
  mouse to tmux, so wheel scrolling and drag-to-copy (tmux-yank) keep
  working.
- nvim read mode (`markdown_read_mode.lua`, render-markdown, zk-nvim) can
  follow links, find backlinks, and search the notebook. But it is an editor
  dressed up as a reader, and it takes setup in every session.

Existing readers come close but do not do the job:

- treemd: polished, but the sidebar shows only the heading outline.
- md-tui: has a file tree, wikilinks, and hover previews (`K`), but its
  parser is hand-written and its author says it does not follow the spec.
- emeraldian: a ratatui TUI with wikilinks, backlinks, and tags, but it is
  built around Obsidian vaults.
- frogmouth: Python and Textual, so it starts slowly.

All of them resolve links with their own heuristics. None uses a markdown
language server, so none gets zk's link resolution, its index, or its
notebook queries (search, tags).

## Goal

ramble is one fast, read-only TUI for reading markdown:

- Renders markdown well, reflowed to the terminal width.
- Follows links between files with browser-style history.
- Uses vim bindings throughout.
- Has a sidebar that shows a file tree, the current file's outline, or both.
- Gets everything that needs notebook knowledge (wikilink resolution,
  backlinks, hover, search, tags) from a configured markdown LSP. zk is
  the main target and marksman is also supported.

ramble replaces both `m` and nvim read mode.

## Approach and why

- **Build from scratch in Rust. Borrow from treemd; do not fork it.**
  About a third of treemd's 32.6k lines are features ramble does not have:
  editing, a jq-like query language (6.5k lines), images, mermaid, and
  its own link parser. The rest is UI and app code. The deciding reason
  is the core: ramble's renderer has to map source byte ranges to screen
  positions, because link highlighting, hints, search, the editor jump,
  and any later mouse support all depend on it. treemd records only heading offsets
  and row ranges, and its own source says click routing would need laid-out
  rects that the renderer does not publish (`src/tui/mod.rs:425`). A fork
  would mean rewriting its renderer, then removing a third of the code
  around it. These parts are worth copying, with MIT attribution: syntect
  highlighting, table rendering, the catppuccin theme, the
  editor-to-watcher-to-reload loop, the keybinding/action layout, and its
  UX ideas (history that restores state, a command palette).
- **Do not build on glow.** glamour outputs plain text and keeps no
  mapping back to the source, and every interactive feature needs that
  mapping.
- **Rust stack:** ratatui 0.30, crossterm 0.29, pulldown-cmark, syntect,
  lsp-types, notify, nucleo, ignore. The same stack is already used in
  tuicr and herdr.
- **Who finds links, who resolves them.** ramble's own parse finds every
  link and its visible text. The LSP resolves targets and reports which
  links are broken. This split is forced by the servers: marksman has no
  `documentLink`, zk's `documentLink` leaves out links it cannot resolve,
  and zk's ranges include syntax that is never drawn (see Review log).
- **Rule for the LSP: best effort without one, and no reimplementing
  anything a markdown LSP does trivially.** Without an LSP, ramble still
  renders, follows relative `[x](path.md)` and `#anchor` links and
  inline code that names an existing file, searches within the page, and
  walks the file tree. Wikilink resolution,
  backlinks, hover, notebook search, and tags need an LSP.

## Scope

### In (v1)

- Rendering CommonMark and GFM: headings, emphasis, lists, task lists,
  tables, footnotes, block quotes, GFM alerts, rules, and code blocks
  highlighted with syntect. Wikilinks (`[[x]]`, `[[x|label]]`) are parsed
  and shown as links.
- Paragraphs reflowed to the render width (see "Render width").
- Theme: catppuccin-mocha by default, changeable in config.
- A real cursor and vim motions (see Keymap).
- Link following:
  - Links to markdown files open in ramble.
  - Anchors scroll to the target heading.
  - External URLs open with `open` or `xdg-open`.
  - Links to non-markdown files open in `$VISUAL` or `$EDITOR`.
  - Inline code spans that name an existing file (see "doc").
- Link cycling with `]l` / `[l` and repeat with `;` / `,`. Hint labels with
  `s` + label.
- History: back and forward. Each entry stores the path, the cursor, the
  scroll position, the sidebar state, and whether the page was raw.
- Sidebar modes: off, files, outline, and split (files above the outline),
  with smart defaults and a configurable split ratio.
- Search within the page: `/ ? n N * #`.
- Marks within the page: `m{a-z}`, `'{a-z}`.
- Yank: `y` on a link copies its target; elsewhere it copies the file path.
- Hover (`K`) for link targets, from the LSP.
- Notebook pickers (one fuzzy overlay): notes, search, tags, backlinks,
  and links. Each picker appears only when a configured source can
  provide its data.
- Broken-link diagnostics from the LSP, shown in a muted style.
- Live reload when the file changes on disk, including after `<leader>o`
  returns from the editor.
- `<leader>o` opens `$VISUAL` or `$EDITOR` at the current file and cursor
  line, as the default editor launcher. (`e` stays the vim end-of-word
  motion.)
- `:` command line and a `g?` help overlay.
- Raw view (`gR`, `:Raw`): the current page's markdown source, one source
  line per row, soft-wrapped by grapheme at the render width and
  highlighted with syntect's Markdown syntax. Per page: history entries,
  resize and live reload keep it; a followed link opens rendered. Motions,
  search, marks, yank, `<leader>o`, review markers and link actions work
  unchanged (links are their full source span). The status line shows
  `RAW`.
- Launchers: configurable commands that suspend ramble, run in the same
  terminal, and reload on return. The editor (`<leader>o`) and three tuicr
  review launches are the defaults (see "Launchers").
- Review markers: comments from a live tuicr session are shown as markers
  on files in the tree and on lines in the content view (see "Review
  markers").
- Print mode: `--print`, or automatic when stdout is not a TTY. ramble
  renders once to stdout as ANSI and exits. It never pages; for a pager,
  run ramble interactively.
- Input from stdin: `cat x.md | ramble` (see "Stdin documents").
- Config at `~/.config/ramble/config.toml`. Built-in defaults mean the file
  is optional, and `ramble --init-config` writes a commented default.

### Out (v1)

- Editing of any kind. Editing happens in `$EDITOR`.
- Splits and tabs. Parked.
- Images, math, and mermaid diagrams. Parked.
- Mouse capture. Off by default and not built in v1, so tmux keeps wheel
  scrolling and drag-to-copy. Parked behind a future `mouse = true`.
- Visual mode. Without mouse capture, tmux copy-mode covers selection.
  Parked.
- A workspace symbols picker. zk does not support `workspace/symbol`.
  Parked.
- More than one LSP server on the same file.
- Opening remote URLs or GitHub repositories as documents.
- Creating notes (`zk.new`) and renaming.
- Raw view line numbers and wrap markers, and a `--raw` print mode.
- Writing tuicr comments from ramble, and showing comment text inline.
  ramble shows where comments are; tuicr is where they are read and written.

## Key decisions

| # | Decision | Rationale |
|---|---|---|
| Q1 | Rust | Same stack as existing projects; the best TUI and markdown crates; no glamour limitations. |
| Q2 | Read-only; `<leader>o` opens `$VISUAL`/`$EDITOR` at the file and line | Editing belongs in nvim, and building it in would multiply the scope. |
| Q3 | Best effort without an LSP; do not reimplement LSP features | Keeps ramble useful on any README while staying small. |
| Q4/Q15 | LSP servers set in config, with zk as the main target and marksman also supported | zk is the daily tool. Config keeps ramble generic. |
| Q5 | Page history with back/forward. Splits and tabs parked | Matches how wikilinks are followed in nvim today. |
| Q6 | Search within the page is native. Everything else comes from the LSP | See Q3. |
| Q10 | Sidebar has four modes: off, files, outline, split. Split ratio is configurable | The user wants the file tree and the outline together. |
| Q11 | Tree root = argument, then VCS root, then `$HOME` | Predictable. The LSP root is separate (see R2). |
| Q12/Q20 | Link cycling with `]l`/`[l` and `;`/`,`; hint labels with `s` | Feels like vim. Hints work like flash.nvim. `f`/`t` are not provided; `;`/`,` belong to links. |
| Q13 | One fuzzy picker overlay for every list | One widget. Works without splits. |
| Q18 | `--init-config` writes the default config; ramble never writes it unasked | The config lives in dotfiles. |
| Q19 | A real cursor with vim motions | `gd`, `K`, and `<leader>o` act on whatever is under the cursor, as in nvim. |
| Q21 | A fixed set of notebook operations. zk-specific calls live in a hard-coded zk adapter; other servers use standard LSP requests | Only zk has notebook commands (marksman's `executeCommand` list is empty), so a generic command layer would have one user. Revisit when a second server needs it. |
| Q22 | Threads and channels, no tokio | The LSP is the only async need. A reader thread and a channel are enough. |
| R1 | ramble's parse finds links; the LSP resolves them | marksman has no `documentLink`; zk's omits broken links and covers undrawn syntax. |
| R2 | Each server has its own root: the directory where its `root_markers` matched. The zk adapter passes that directory as the notebook path | zk finds notebooks only by walking up from the path it is given. |
| R3 | Mouse capture off in v1 | Keeps tmux wheel and drag-to-copy, which `m` protects today. |
| Q23 | Launchers: a generic list of commands bound to keys, with the editor and tuicr as defaults | One code path for every external TUI; tuicr (git, jj, hg) and others such as lazygit or jjui need no ramble change. |
| Q24 | Review keys `<leader>rr` (this file), `<leader>rw` (uncommitted changes to it), `<leader>rd` (a folder) | No collision with `<leader>z…`, `<leader>e`, `<leader>o`. |
| Q25 | Show markers for comments in a live tuicr session, on files and lines | The user wants to see where review comments are while reading. Read-only; text stays in tuicr. |
| R4 | Positions converted using a per-server encoding, not assumed UTF-16 | zk 0.15.6 sends code-point offsets and does not advertise `positionEncoding`. |

## Architecture

```
ramble
├── cli      args → (tree root, start target), TTY detection, --print, --init-config
├── config   load TOML over built-in defaults; servers; leader key
├── doc      pulldown-cmark (with offsets) → Document { source, blocks, headings, links }
├── render   Document + width + theme → RenderedPage { lines, srcmap }
├── lsp      stdio JSON-RPC client; one thread per server; requests return via channel
├── notebook operations (notes/search/tags/backlinks/links) → zk adapter | LSP | local
├── review   tuicr session discovery and comment polling → markers
├── nav      history of Page { path, cursor, scroll, sidebar }; back/forward
├── ui       content view, sidebar, picker, hover popup, hints, search bar, cmdline, status
└── app      event loop: key | fs-watch | lsp | review | resize → state → draw
```

### Each unit

- **cli**
  - Tree root: for a file argument, its parent directory; for a directory
    argument, that directory. Then the VCS root (`.git`, `.jj`, or `.sl`
    above it), then `$HOME`.
  - Start target, in order of precedence:
    1. A file argument opens that file. Stdin is ignored.
    2. A directory argument opens the file tree with nothing loaded.
    3. No argument, and stdin is a pipe or a file: read the document from
       stdin (see "Stdin documents").
    4. No argument, and stdin is a terminal: open the file tree from the
       current directory.
  - Print mode: if stdout is not a TTY, or `--print` is given, ramble
    renders once to stdout and exits. In print mode with no document
    (case 2 or 4), ramble prints a usage error and exits with status 2.
- **config**
  - Data structures with serde defaults. A user file overrides the
    defaults one field at a time.
  - Each server has a `kind`: `zk`, `marksman`, or `generic`. The kind
    selects built-in behaviour (the zk adapter, position encoding, startup
    steps). Built-in defaults define one zk and one marksman server.
  - `--init-config` writes `config.default.toml`, which is embedded with
    `include_str!` and fully commented with both default servers written out, to
    `~/.config/ramble/config.toml`. It refuses to overwrite an existing file.
- **doc**
  - Has no dependency on rendering.
  - Input is read as UTF-8. Invalid bytes are replaced with U+FFFD and the
    status line shows "not valid UTF-8". A file whose first 8 KiB contain
    a NUL byte is treated as binary: ramble shows a message and does not
    render it.
  - Records byte ranges for every block, heading, and link. Each link has
    two ranges: the full source span and the visible-text span. Wikilinks
    use pulldown-cmark's wikilink support.
  - Heading slugs follow the GitHub algorithm so `#anchor` links resolve.
  - A leading YAML front-matter block is metadata: not rendered, no headings or links.
  - Code-path links. `doc` records every inline code span outside a link;
    it does no I/O. On each load and reload the app keeps the spans whose
    text names an existing regular file and adds them as links of kind
    `CodePath`:
    - Forms: a relative path, an absolute path, or `~/...`, optionally
      followed by `:LINE` or `:LINE:COL`. The full text is tried first,
      then with the suffix stripped. Spans with whitespace inside, spans
      over 512 bytes, and URLs are never links.
    - A relative path is tried against the current file's directory, then
      its VCS root, then the tree root (stdin: the working directory, its
      VCS root, the tree root). The first existing file wins.
    - Drawn in the code colour with a link underline. They take part in
      `]l` / `[l`, hints, and the links picker (detail: the resolved path).
    - Following: a markdown file opens in ramble at LINE; any other file
      opens in the editor with `+LINE`. A file deleted since the load
      gives "No such file: <text>". LSP results never apply to them.
- **render** (the core)
  - Lays out a `Document` for one width, producing styled `Line`s.
  - Also produces `srcmap`: a two-way map between source byte ranges and
    `(row, col_start..col_end)` screen spans, one span per drawn inline
    segment. Bytes that are never drawn (link syntax, emphasis markers,
    fence lines) have no span; a lookup on them returns the nearest drawn
    position.
  - Users of the srcmap:
    - Link highlighting, from each link's visible-text span.
    - Placing hint labels.
    - Search hits, which are matched against the rendered text and mapped
      back to a source line.
    - The cursor's source line for `<leader>o`.
    - Syncing the outline to the cursor.
  - Re-runs on resize.
  - Print mode uses the same lines and writes them out as ANSI.
- **lsp**
  - A small hand-written client over stdio.
  - Messages: `initialize`, `initialized`, `didOpen`, `didClose`,
    `documentLink`, `definition`, `hover`, `references`,
    `executeCommand`, `publishDiagnostics`, and `shutdown`.
  - `didOpen` uses `languageId = "markdown"`. zk ignores other ids.
  - One reader thread per server. Responses come back as
    `AppEvent::Lsp { server, request_id, page_id, result }`.
  - Records the capabilities the server reports.
  - Choosing a server: the first configured server whose `root_markers`
    are found above the file. That directory is the server root. At most
    one process runs per (server, server root). Servers start lazily.
  - Each server process starts with its working directory set to the
    server root. For `kind = "zk"`, ramble sends `zk.index` with the
    server root after `initialized`, because `zk lsp` indexes only at startup from a working directory
    inside the notebook, and afterwards only on `didSave`, which ramble
    never sends.
  - Positions: the client offers `positionEncoding` `["utf-8", "utf-16"]`
    in `initialize` and uses whatever the server picks. If the server
    reports none, it uses the default for the server's kind: `utf-32`
    (code points) for zk, `utf-16` otherwise. `position_encoding` in the
    server config overrides it. All conversion to and from byte offsets goes through
    one function.
  - Paths: every file URI is canonicalized before it is compared, because
    servers may return a different form of the same path (for example
    `/private/tmp` for `/tmp` on macOS).
  - If a server crashes or fails to start, the status line shows it, and
    ramble continues in no-LSP mode for that root.
- **notebook**
  - Turns an operation into items `{label, detail, path, line}` by trying
    these sources in order:
    1. The zk adapter, when the server is `kind = "zk"` (see "zk adapter").
    2. The matching standard LSP request.
    3. ramble's local fallback.
  - An operation with no source is hidden from the keymap help and the
    command line.
- **review** (see "Review markers")
  - A background thread that polls tuicr's session CLI and sends
    `AppEvent::Review(markers)` when the comment set changes.
  - Has no dependency on rendering or the LSP.
- **nav**
  - Plain data plus push, back, and forward.
  - Following a link from a page that is not at the top of the history
    stack clears the forward entries.
  - Each page visit gets a new `page_id`.
- **ui**
  - ratatui widgets only, no logic.
  - The status line shows the path, the LSP state (`zk ●`, `zk ○`
    starting, `—` none), the position as a percentage, and the depth of the
    back history. A dimmed `g? help` hint sits left of the LSP state
    whenever the line shows these fields (not while the search or sidebar
    filter prompt owns the row). The hint is dropped first when the line
    is too narrow, before the path or the LSP label is truncated.
  - The TUI sets the terminal title (OSC 0/2) to `ramble — <status-line
    title>` (the path relative to the tree root, else the full path;
    `[stdin]`), or `ramble` with no page, with control characters removed,
    and updates it only when it changes. It saves the old title with
    XTWINOPS `CSI 22;0 t` at start and restores it with `CSI 23;0 t` at exit
    and on panic. After a launcher it sends the title again (the command may
    have set its own). Under tmux (with `allow-set-title`, on by default)
    the title becomes `#{pane_title}`, and tmux's title stack restores it on
    exit. Window names come from `automatic-rename-format` (default
    `#{pane_current_command}`), so to see the file there, put
    `#{pane_title}` in `automatic-rename-format`, `window-status-format` or
    `set-titles-string`. Print mode never sets a title.
- **app**
  - Owns the state and applies actions.
  - Keymap: a key sequence maps to an `Action`. v1 makes only `<leader>`
    and launcher keys configurable; full remapping is parked.
  - Runs launchers: leaves the alternate screen, restores the terminal,
    runs the command, waits, re-enters, redraws, and reloads the page.
  - Drops any LSP reply whose `page_id` is not the current page's, or
    whose document version is older than the current one.

### Data flow: opening or reloading a file

1. Read the file, build the `Document`, and render it. It is shown
   straight away, with every link from the local parse highlighted.
2. In parallel, ramble sends `didOpen` (with the full text and a version
   number) and then `documentLink`. A reload follows the same path: it
   bumps the version and sends `didOpen` again with the new text. zk
   replaces the stored document on each `didOpen`. `didClose` alone does
   not clear zk's copy, so ramble does not rely on it.
3. When the `documentLink` reply arrives, ramble matches each LSP range to
   the local link it overlaps and records the resolved target. LSP ranges
   are never drawn directly.
4. Diagnostics arrive whenever the server sends them, in any order
   relative to the `documentLink` reply. A link that a diagnostic covers
   switches to the muted style.
5. `gd` on a link resolves it in this order: the target from
   `documentLink`, then a `definition` request, then the local parse.
   The file comes from the first source that answers. The `#anchor` always
   comes from the local parse, because zk drops the fragment from both
   `documentLink` and `definition`. In the local parse a wikilink with no
   extension gets `.md`; a markdown link with no extension gets `.md` when
   that file exists and the bare path does not (zk's rule, and its default
   link style `[x](note)`).

### Render width

- Interactive: `min(terminal width - sidebar width, render.max_width)`.
- Print mode: `--width N` if given, else `$COLUMNS` if set, else the
  width of stdout if it is a terminal, else 80. Then capped at
  `render.max_width`.

### Stdin documents

A document read from stdin has no path:

- Its title is `[stdin]`. Relative links resolve against the current
  directory.
- No LSP is started for it. The sidebar `auto` default picks `outline`.
- `<leader>o` and live reload are disabled, with a status message.
- Following a link to a real file opens it normally, with the LSP. `C-o`
  returns to the stdin page, which is kept in memory.
- Keys are read from `/dev/tty`, because stdin is the document.

### Error handling

- **A missing or broken LSP** shows `—` in the status line. LSP-backed
  features are hidden and nothing else fails.
- **An LSP request that is slow** (more than 2s) shows a spinner in the
  status line. Replies for a page the user has left, or for an older
  version of the document, are dropped (see app).
- **A link that cannot be resolved** shows a status message, and history
  does not change.
- **A file deleted while open** shows a banner and keeps the last rendered
  content.
- **A config parse error** prints the error with its line number and exits
  before entering the TUI.

## Launchers

A launcher is a command bound to a key. Running one suspends ramble's TUI,
runs the command in the same terminal with the terminal restored, waits
for it to exit, then resumes ramble and reloads the current page.

```toml
[[launch]]
name = "edit"
key = "<leader>o"
command = ["${editor}", "+${line}", "${file}"]

[[launch]]
name = "review"
key = "<leader>rr"            # annotate this document; works without VCS
command = ["tuicr", "--file", "${file}", "--line", "${line}"]

[[launch]]
name = "review-changes"
key = "<leader>rw"            # uncommitted changes to this document
command = ["tuicr", "-w", "-p", "${file}", "--line", "${line}"]
needs_vcs = true

[[launch]]
name = "review-dir"
key = "<leader>rd"            # annotate a folder
command = ["tuicr", "--file", "${dir}"]
```

- Variables, substituted per argument (no shell):
  - `${file}`: absolute path of the current document.
  - `${line}`: 1-based source line under the cursor.
  - `${dir}`: the folder selected in the file tree if the sidebar has
    focus, else the current document's folder.
  - `${vcs_root}`: the VCS root (`.git`, `.jj`, or `.hg`/`.sl` above the
    file), if any.
  - `${editor}`: `$VISUAL`, else `$EDITOR`, else `vi`.
- Working directory: `${vcs_root}` if there is one, else `${dir}`. tuicr
  detects git, jj, and Mercurial from the working directory.
- A launch is unavailable, with a status message, when a variable it uses
  has no value (for example `${file}` for a stdin document) or when
  `needs_vcs = true` and there is no VCS root.
- `:Launch <name>` runs a launcher by name. `g?` lists the launchers.
- User `[[launch]]` entries replace a default with the same `name` and add
  the rest. `[[launch]] name = "review" disabled = true` removes one.
- A non-zero exit shows the exit code in the status line.

## Review markers

ramble shows where comments are in a live tuicr session for the notebook or
repo being read. It never reads comment text into the page and never
writes comments.

**Session discovery.** tuicr keys a session to a directory, and which one
depends on how it was started (verified with tuicr 0.25.0): `tuicr --file
<path>` (`<leader>rr`, `<leader>rd`) uses the file's folder, or the folder
passed to it, even when run from the repo root; `tuicr -w -p`
(`<leader>rw`) uses the repo root. So the review thread runs
`tuicr review list --repo <dir>` for a set of directories and unions the
results: the current file's folder, each ancestor of it up to and including
`${vcs_root}` (at most 8 levels above the folder), and `${vcs_root}`
itself. Outside a VCS repository the set is just the file's folder.
For each directory it keeps the sessions with `"active": true`, plus the
last session it saw active under that directory ("sticky"): tuicr marks a
session active only while its process runs (verified with tuicr 0.25.0),
so without the sticky session markers would vanish the moment you quit
tuicr. A different session becoming active under the same directory
replaces that directory's sticky one.

**Comments.** For each of those sessions, it runs
`tuicr review comments --session <slug> --repo <dir>`, with `<dir>` the
directory the session was listed under. Each comment has
`path` (relative to that `<dir>`; ramble resolves it against `<dir>`
before matching the current file and tree entries), `start_line`,
`end_line`, `side`, and
`lifecycle_state` (`local_draft`, `pushed_draft`, or `submitted`; tuicr
has no resolved state). ramble keeps comments with `side = "new"`, because
comments on removed lines have no place in the current file, and shows
every lifecycle state.

**Polling.**
- Discovery every 5 s; comments every 2 s while an active session exists.
- Polling pauses while a launcher is running (ramble is suspended) and
  runs once immediately when it returns; the sticky session makes the
  comments from that `<leader>rr` run appear as soon as you come back.
- Comments typed in the TUI appear in `tuicr review comments` straight
  away, before `:w` (verified with tuicr 0.25.0).
- If `tuicr` is not on PATH, the review thread does not start.
  `review.enabled = false` turns it off.

**Display.**
- File tree: a marker (`●`, and a count when the sidebar is wide enough)
  after each file with comments, and a dimmer marker on each folder that
  contains such files.
- Content view: a marker in a one-column gutter on every screen row whose
  source line falls in a comment's `start_line..end_line`. Source lines
  map to screen rows through the srcmap.
- Status line: `review 3` when the current file has comments.
- `]r` / `[r` jump to the next or previous commented line.
- A line marker whose line number is past the end of the file is shown on
  the last line.

**Limits.**
- Line numbers are the ones tuicr stored. If the file changes after a
  comment is written, markers can drift; ramble does not try to track
  them.
- tuicr's session JSON format is not a public API; ramble uses only the
  `tuicr review` CLI, which is documented in tuicr's `docs/REVIEW_CLI.md`.

```toml
[review]
enabled = true
command = "tuicr"
```

## Sidebar

| Mode | Shows |
|---|---|
| off | content only |
| files | file tree from the tree root; `.gitignore` respected; markdown files highlighted, other files dimmed (`sidebar.show_all` toggles them) |
| outline | headings of the current file; the heading containing the cursor is marked `◂` |
| split | files on top, outline below; `sidebar.split_ratio` sets the share |

- **Default** (`sidebar.default = "auto"`): no argument or a directory
  argument opens in `files`; a file argument or stdin opens in `outline`.
  `split` is never chosen automatically, so set it in config if you want
  it.
- `<leader>e` cycles through off, files, outline, and split.
- Sidebar keys: `j k`, `h`/`l` to collapse and expand, `o`/`Enter` to open
  a file or jump to a heading, `gg G`, `/` to filter.
- `C-w h`, `C-w l`, and `C-w w` move focus between the sidebar and the
  content.
- The file tree follows the current file: it expands the file's directory
  and moves the selection to the file. If the file is outside the tree
  root, the tree keeps its root, shows no selection, and the sidebar title
  shows the file's path.

Picker keys, each written in full:

| Keys | Picker |
|---|---|
| `<leader>zf` | notes |
| `<leader>zs` | search |

| `<leader>zb` | backlinks (same as `grr`) |

Notes:

- `<leader>` defaults to space.
- `C-i` and `Tab` send the same byte in most terminals. ramble binds both
  to forward and binds nothing else to `Tab`. It does not depend on the
  kitty keyboard protocol.
- `gd` on a code-path link (inline code naming a file) never asks the
  LSP; see "doc".
- `f`/`F`/`t`/`T` are not provided in v1. `;`/`,` repeat link motions.
- Command line: `:e <path>` opens a file (relative to the current file's
  directory), `:q` quits, `:Notes`, `:Search <query>`, `:Tags`,
  `:Backlinks`, `:Links`, `:Launch <name>`,
  `:Sidebar <off|files|outline|split>`, and `:Raw`.
- `g?` works from the content and from a sidebar pane. The help overlay
  is a centered modal, grouped by section (General, Motions, Scrolling,
  Links, History, Search & marks, Review, Sidebar, Pickers, Launchers,
  Commands, Help). Its rows come from a bindings table checked against the
  keymap by a test, plus the configured launchers (with their keys; keyless
  ones as `:Launch <name>`; `needs_vcs` ones greyed outside a repository)
  and the `:` commands. Rows whose action cannot do anything now are
  hidden: no `K` without a hover-capable server, no zk pickers without zk,
  no `]r` without review comments, no `n`/`N` before a search, and so on.
  In the overlay `j k C-d C-u gg G` scroll, `/` filters (Enter keeps the
  filter, Esc clears it), and `q`, `Esc` or `g?` close it. Bare `?` stays
  backward search.
- The picker uses nucleo for fuzzy matching over items already loaded:
  `C-n`/`C-p` move, `Enter` opens, `Esc` closes. `search` first prompts
  for a query, sends it once, and then fuzzy-filters the results.
  ramble passes the query to zk unchanged, so zk's search syntax applies
  (a word prefix needs `*`, and a leading `-` means NOT).

## Notebook operations

| Operation | zk | marksman | no LSP |
|---|---|---|---|
| notes | `zk.list` | file walk | file walk |
| search | `zk.list` + `match` | — | — |
| tags | `zk.tag.list`, then `zk.list` + `tags` | — | — |
| backlinks | `references` (see below) | `references` (see below) | — |
| links | local parse, targets from `documentLink` | local parse, targets from `definition` on follow | local parse |

Order of sources: the zk adapter, then the standard LSP request (if the
server reports the capability), then the local fallback.

**Backlinks of the current page.** `references` answers for whatever is at
the position it is sent. On a link, zk returns the backlinks of the link's
target; marksman needs the position to be on a link, heading, or tag. So
ramble never sends the cursor position for this picker:

- zk: position 0:0, which is not on a link, so zk returns references to
  the current note.
- marksman: the position of the document's first heading. If the
  document has no heading, the picker is hidden.

Choosing a backlink opens the note with the cursor on its first link
(wikilink or markdown) whose target, by canonical path, is the page the
picker was opened from: the `documentLink` target if the server gave one,
else local resolution. With no such link it goes to the line the server
reported (zk reports the first substring hit of the target's name, often
not the link), and redoes the search when the page's `documentLink` reply
arrives, unless the cursor has moved by then.

### zk adapter

A small module with one function per operation. Each calls
`executeCommand` with fixed arguments, passing the server root as the
notebook path (`args[0]`). zk finds a notebook only by walking up from
that path, so ramble's tree root would fail for a notebook inside a git
repo.

| Function | Call | Result → item |
|---|---|---|
| `notes()` | `zk.list` `{select: [title, absPath], sort: [modified]}` | label = `title`, path = `absPath` |
| `search(q)` | `zk.list` `{select: [title, absPath], match: [q]}` | label = `title`, path = `absPath` |
| `tags()` | `zk.tag.list` | label = `name`, detail = `note_count` |
| `notes_by_tag(t)` | `zk.list` `{select: [title, absPath], tags: [t]}` | label = `title`, path = `absPath` |

Choosing a tag in the tags picker opens a second picker from
`notes_by_tag`. The zk end-to-end test covers every function, so a change
in zk's result fields fails a test.

### Server config shape

```toml
[[lsp.server]]
kind = "zk"
command = ["zk", "lsp"]
root_markers = [".zk"]
# position_encoding = "utf-32"   # default for kind = "zk"

[[lsp.server]]
kind = "marksman"
command = ["marksman", "server"]
root_markers = [".marksman.toml", ".git"]
```

- `kind` is `zk`, `marksman`, or `generic`. `generic` gets standard LSP
  requests only.
- Servers are tried in the order they appear in the config, so a `.zk`
  notebook inside a git repo gets zk, with the notebook directory as its
  server root.

## Testing

Each test below names the checklist step that must make it pass.

- **doc and render** (steps 2, 3): golden tests. A fixture `.md` at several
  widths is checked against a snapshot of plain text with style markers
  (`insta`). Fixtures include non-ASCII text, emoji, and CJK. Property
  tests over generated markdown check that:
  - every link's visible-text span maps to at least one screen span;
  - every drawn screen cell maps back to a source byte inside its block;
  - converting source → screen → source returns a byte inside the same
    drawn segment.
- **position conversion** (step 10): table tests for the byte ↔ position
  function in `utf-8`, `utf-16`, and `utf-32`, over lines with `é`, `😀`,
  and CJK, including positions at the end of a line.
- **LSP client** (step 10): an integration test against a scripted fake
  server (a small binary in `tests/`). It covers message framing,
  request/response matching, `positionEncoding` negotiation,
  diagnostics arriving before a reply, and a crashed server.
- **app** (steps 5–9, 11–13): state-machine tests that send events into
  `App` without a terminal, using the fake server for LSP events. They
  assert on the cursor, history, sidebar mode, picker contents, banners,
  and link styles. Cases include:
  - an LSP reply for a page the user has left is dropped;
  - an LSP reply for an older document version is dropped after a reload;
  - the spinner shows after 2s without a reply (with an injected clock);
  - an fs-watch change event reloads the page and sends `didOpen` with a
    new version;
  - an fs-watch delete event shows the banner and keeps the content;
  - `<leader>o` runs a fake editor (a script set as `$VISUAL` that
    appends a line), then the page shows the new line;
  - following an anchor link with zk returning a fragment-less target
    lands on the heading.
- **launchers** (step 7): app tests with a fake command (a script that
  records its argv and cwd): variable substitution, working directory,
  unavailable when a variable is empty or `needs_vcs` fails, user entries
  replacing defaults, reload on return.
- **review markers** (step 14): the review module is tested against a fake
  `tuicr` script that returns canned `review list` / `review comments`
  JSON: active-session filtering, `side = "old"` dropped, path mapping,
  polling pause and resume. An app test checks tree and gutter markers and
  `]r`. One end-to-end test runs the real `tuicr --file` in a tmux pane,
  adds a comment with `tuicr review add`, and checks ramble shows the
  marker; it is skipped if `tuicr` or `tmux` is missing, with the skip
  printed.
- **live reload, real watcher** (step 7): one test that writes to a temp
  file and waits up to 2s for the reload event from `notify`.
- **zk end to end** (steps 10, 11, 13): a fixture notebook in
  `tests/fixtures/zk/` with a `.zk/` folder, nested inside a fixture git
  repo. The test starts with no index database and runs the real
  `zk lsp`. It checks that `zk.index` runs on start, then checks
  documentLink (including a link after an emoji), definition, hover,
  references at 0:0, diagnostics for a broken link, and each zk adapter
  function (`notes`, `search`, `tags`, `notes_by_tag`). It is skipped if `zk` is not on PATH, with the skip
  printed.
- **marksman end to end** (step 13): the same fixture notebook with a
  `.marksman.toml`. It checks definition, hover, and references from the
  first heading. It is skipped if `marksman` is not on PATH, with the skip
  printed.
- **print mode** (step 4): `ramble --print --width 80 fixture.md` diffed
  against `expected.ansi`. A second test runs ramble with stdout piped and
  no `--print`, and checks it prints and exits. A third checks `$COLUMNS`
  is used when `--width` is absent.
- **cli** (step 4): stdin precedence (`ramble f.md < other.md` shows
  `f.md`), print mode with no document exits 2, a binary file shows a
  message.
- **config** (step 9): field-by-field override of defaults,
  `--init-config` refusing to overwrite, and a parse error reporting its
  line.
